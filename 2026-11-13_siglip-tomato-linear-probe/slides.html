Zero-shot vs a frozen-backbone
linear probe: SigLIP on tomato maturity

How much does a 1,538-parameter head on a frozen SigLIP encoder improve over classifying from text prompts alone?

google/siglip-base-patch16-224 · Tomato Maturity Detection & Quality Grading · PyTorch + 🤗 Transformers · Colab T4

Say: "I took SigLIP, a vision-language model, and asked one question: how much do I gain over its zero-shot ability by training only a tiny linear layer on top of its frozen image features?"

Why open with the question: it frames every later slide as evidence for or against a single claim. Graders like a clear hypothesis.

Problem

Why classify tomato maturity automatically?

The problem

  • Harvest timing is conventionally judged by eye, from skin colour.
  • Picking off-peak causes substantial losses, especially for robotic harvesting.
  • Manual inspection is labour-intensive and inefficient for farmers.
  • Expert labels are expensive: this dataset was labelled with an agricultural domain expert.

Applications

  • Robotic harvesting: pick only fruit at peak maturity
  • Post-harvest sorting & packing lines: route fruit by ripeness
  • Quality assessment along the supply chain
Why this approach fits: zero-shot needs no labels; a linear probe needs few labels and seconds of compute. One frozen backbone can serve several such tasks, each with its own tiny head.

Motivation and applications: Data in Brief (2023), "An extensive real-world in field tomato image dataset…", PMC10618421

Say: "Tomato harvest timing is usually judged by eye from skin colour. The dataset authors point out that picking at the wrong ripeness causes substantial losses, especially for harvesting robots, and that manual inspection is slow and labour-intensive. Automating it supports robotic harvesting, sorting and packing lines, and quality checks in the supply chain."

Why this framing matters: it justifies the method. Expert labels are costly, so it's worth asking how far you get with zero labels (zero-shot), and how much a handful of labels plus a tiny head adds (linear probe). The "one backbone, many heads" point is a practical bonus. A farm system could add a fresh-vs-defect head on the same frozen features. If asked about deployment: the 93M-parameter encoder still has to run at inference time; freezing makes training cheap, not inference.

Model

SigLIP: CLIP with a pairwise sigmoid loss

  • Two towers: a ViT-B/16 image encoder and a text encoder, both mapping into a shared 768-d space.
  • CLIP trains with a softmax over the whole batch: "which of these N captions matches this image?"
  • SigLIP scores each image–text pair independently with a sigmoid: "does this pair match, yes or no?"
  • No batch-wide normalisation → simpler, more memory-efficient, strong at small batch sizes.
# SigLIP pair score
logit = cos(img, txt)
        * exp(logit_scale)
        + logit_bias

# per pair: sigmoid(logit)
# → class scores need not sum to 1

Zhai et al., "Sigmoid Loss for Language Image Pre-Training", ICCV 2023 · arxiv.org/abs/2303.15343

Say: "SigLIP is from Google, 2023. It's like CLIP, an image tower and a text tower in a shared space, but instead of a softmax across the whole batch, each image–caption pair is its own yes/no sigmoid question."

Why it matters here: the same shared space is what makes zero-shot work. A text vector for "ripe red tomato" lands near photos of ripe tomatoes. If asked "why don't the probabilities sum to 1?": each class is an independent sigmoid, and for top-1 we take the argmax.

Data

931 unique original photos, augmented copies excluded

  • 2 classes: Immature, Mature (~500 originals each as published)
  • The dataset also ships augmented copies (rotated, flipped, zoomed). They were excluded, because random splitting would leak near-duplicates of test images into training.
  • Exact duplicate files removed by MD5 hash → 931 unique images
  • Stratified 70 / 15 / 15 split, seed 42 → ~700 / ~150 / ~150

Dataset: Mendeley Data s42kpg8h37 (mirrored on Kaggle) · paper: PMC10618421

Say: "One data decision matters a lot. The dataset includes 4,000 augmented images that are just rotated and flipped versions of the 1,000 originals. If I split randomly across all of them, a rotated copy of a test tomato could be in training. That's leakage, and it inflates the score. So I used only the originals, removed byte-identical duplicate files, which left 931 unique images, and used a stratified split: 651 train, 140 validation, 140 test."

Why stratified: each split keeps the same 50/50 class balance, so accuracy numbers are comparable across splits.

Preprocessing hygiene

Match the pre-training input exactly

# manual pipeline
img = img.resize((224, 224), BICUBIC)
x = np.asarray(img)      # (224,224,3) HWC 0–255

     .permute(2, 0, 1)   # (3,224,224) CHW

# vs AutoProcessor: max |diff| = 0.0078
#   = 2/255 = one 8-bit pixel level
# batch → (B, 3, 224, 224) NCHW

Mean = std = (0.5, 0.5, 0.5), from SigLIP's processor config, not CLIP's 0.481…/0.268…

Say: "SigLIP was trained on 224-pixel images split into 16-by-16 patches. That's a 14-by-14 grid, 196 tokens. I resize to 224, convert from height-width-channels to channels-first because PyTorch expects that, and normalise to minus one to one with mean and std 0.5. I did it by hand and compared it with the official AutoProcessor. The largest difference was 0.0078, which is one pixel-intensity step, so they match."

Why it matters: a model's features only mean something on inputs that look like its training data. CLIP's normalisation constants are different. Copying a CLIP snippet would silently shift every input. Your run: max |manual − processor| = 0.0078, which is exactly 2/255, i.e. one 8-bit brightness level after scaling to [−1, 1]. The worst pixel differs by one rounding step from resampling, so the pipelines are effectively identical.

Say: "I set requires_grad to False on every vision-encoder parameter, so no gradients flow into it and the optimiser can't change it. The optimiser only receives the head's parameters. That's 92.9 million frozen versus 1,538 trainable, 0.0017% of the model, which is 768 times 2 weights plus 2 biases."

Why freeze: 651 training images against ~93M parameters would overfit and could wreck the pre-trained features. Training is seconds instead of minutes, and a linear probe is the standard way to measure feature quality (CLIP and SigLIP papers both report it). Speed trick: because the backbone is frozen and there's no augmentation, each image's 768-d embedding never changes, so I compute embeddings once and train on the cache. I verified it's identical to the full forward pass (torch.allclose → True).

How to read it: if validation loss rises while train loss keeps falling, that's overfitting, and that's why I select by validation. The test set is never used for any choice, so its score stays an unbiased estimate.

Say: "On the 140 held-out test images, zero-shot gets 78.6% and the frozen backbone plus linear probe gets 99.3%, plus 20.7 points from training 1,538 parameters. The confusion matrices show where: zero-shot misses 30 of 75 mature tomatoes (Mature recall 0.60), all called immature. The probe makes a single error, one immature tomato called mature."

Precision for Mature = of everything called Mature, how much really was. Recall = of all truly Mature tomatoes, how many were found. Be honest about size: 140 test images, so one image ≈ 0.71 points, and 99.3% is literally one mistake from one seed. Read the zero-shot row like this: Immature recall 1.00 but precision 0.68, because everything uncertain gets dumped into Immature. Mature precision 1.00 but recall 0.60: when it says Mature it's right, but it misses 40% of them.

Error analysis · borderline tomatoes

Zero-shot misses turning tomatoes; the probe doesn't

Say: "Top row: images zero-shot got wrong; bottom row: the probe's mistakes. Every zero-shot miss is a tomato the expert labelled mature that is yellow, yellow-green, orange or only blushing red, not the deep red the prompt describes. The probe's single error is a pale yellow-green tomato labelled immature, a genuinely borderline case."

Why zero-shot fails here: the prompts only say "green" or "red", while the expert labels are based on maturity, which isn't purely colour. The probe learns the actual decision boundary from labelled examples. The probe made 1 error; with 140 test images, don't claim it is "solved".

Takeaways

What this shows, and what it doesn't

Findings

  • Zero-shot SigLIP: — with no labels
  • 1,538 trainable parameters → — (—)
  • Zero-shot errs one way: 30/75 Mature called Immature; the probe learns the expert's boundary (1 error / 140)

Limits → next steps

  • Small, single-source dataset; single seed → repeat over seeds, report mean ± std
  • Binary labels only → finer ripeness stages (e.g. turning, pink) if labelled data exists
  • Backbone fully frozen → unfreeze the last 1–2 ViT blocks with a low learning rate

Code: notebook + README + requirements in the team repo · Questions?

Say: "The takeaway: SigLIP's frozen features are already good enough that a single linear layer goes from 78.6% to 99.3%. The information was already in the features; the text prompts just put the class boundary in the wrong place. The limits: one small dataset, one seed, two classes. Next I'd run multiple seeds and try unfreezing the last couple of transformer blocks."

Naming your own limitations before the grader does is one of the strongest signals of research maturity.
